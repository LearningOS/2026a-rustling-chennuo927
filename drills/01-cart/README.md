# 空白页训练 01 · 购物车结算器

预计 30–60 分钟，成品大约 50–80 行。

规矩只有一条：**先写签名，再写函数体。** 签名的部分 `cargo check` 能过之前，不要写任何逻辑。

---

## 一、需求

三种商品，用**一个 enum** 表示：

| 变体 | 字段 | 税率 |
|---|---|---|
| `Item::Book` | `title: String`, `price_cents: u32` | 0% |
| `Item::Food` | `name: String`, `price_cents: u32` | 0% |
| `Item::Toy` | `name: String`, `price_cents: u32` | 13% |

字段名必须一字不差（测试要用）。金额一律用整数「分」，不要引入浮点数。

## 二、必须提供的公开 API

函数名和职责如下，**参数类型和返回类型由你自己定**（测试文件里能推出来）：

| 名字 | 职责 |
|---|---|
| `subtotal` | 所有商品的税前价格之和 |
| `tax_cents` | 单件商品的税额 |
| `total` | 税前总额加上每一件商品的税 |
| `cheapest` | 最便宜的那件商品；空购物车返回 `None`；价格并列时返回**最先出现**的那件 |
| `apply_discount` | 给所有商品打折，见下 |

规则细节：

- 税额四舍五入到分。13% 一律用整数算：`(price * 13 + 50) / 100`。
- `apply_discount(items, percent)` 里 `percent` 是 `u8`，表示打掉百分之几（`50` = 打五折）。
  - 新价格向下取整到分：`price * (100 - percent) / 100`。
  - `percent` 超过 `100` 时返回 `Err(...)`，**并且一件商品都不能改**（想想为什么这要求你必须先校验后修改）。
  - 合法时返回 `Ok(())`。
- `Item` 需要 `#[derive(Debug, Clone, PartialEq)]`，否则测试打印不出来。

## 三、跑起来

```bash
cd drills/01-cart
cargo test
```

第一次跑一定编译失败 —— `src/lib.rs` 是空的，编译器会一条一条告诉你还缺什么。这就是你的路线图。

## 四、动手前的 5 分钟

在纸上（或注释里）先写这份**数据清单**，写完再敲键盘：

| 值 | 类型 | 谁拥有它 | 谁借用它 |
|---|---|---|---|
| 一件商品 | `Item` | | |
| 一堆商品（只读） | | | |
| 一堆商品（要改） | | | |
| 「最便宜的那件」 | | | |

最后一行是关键：`cheapest` 返回的东西**借用**了输入的购物车，还是复制了一份出来？这两种选择会让签名长得完全不同，也会让函数体的写法完全不同。

## 五、卡住了怎么办

把**完整报错原文**和你**自己的猜测**发给我。我只回答三类问题：

1. 类型、签名、「这个值应该是什么类型」
2. 借用/所有权报错到底在说什么
3. 思路层面的引导（「试试先想想它在哪一行失效」）

**我不会给你实现代码。** 这是训练，不是抄写。

## 六、全绿之后再想（不给答案）

1. 如果要求 `cheapest` 改成返回 `Option<Item>`（自己拥有一份），签名要改哪里？调用方要付出什么代价？
2. `subtotal` 的参数为什么是 `&[Item]` 而不是 `Vec<Item>`？写 `Vec<Item>` 会发生什么？
3. `apply_discount` 如果先循环改价格、循环里再检查 `percent`，会破坏哪条需求？
4. `tax_cents` 里你匹配的是 `&Item` 还是 `Item`？如果写 `match item { Toy { .. } => ... }`（少了 `&`）编译器会说什么？
5. 如果三个变体都长一样（都是 `{ name: String, price_cents: u32 }`），还能不能用 enum？这时候 enum 相比「一个 struct 加一个 `kind: String` 字段」的优势是什么？

## 七、收尾

全部通过以后，**隔一天**把 `src/lib.rs` 删空，凭记忆重写一遍，再跑测试。第二遍的速度才是真实水平。能做到十五分钟内写完，就可以进训练 02（会在 `Result` 和自定义错误类型上继续加压）。
